# 進捗管理表 利用マニュアル (v3 / Lite)

更新日: 2026-04-15

## バージョン選択

| 版 | 向いているケース |
|---|---|
| v3 | 実績開始日 / 実績完了日まで管理したい |
| Lite | 計画と進捗だけを軽く管理したい |

## 表の見方

| 列 | 項目名 | 入力内容 |
|---|---|---|
| A | LV | 自動入力 |
| B | No. | 自動採番 |
| C-F | TASK | 階層に応じたタスク名。LV2-LV4 は C列に注意マーク表示あり |
| G | タスク詳細 | 補足情報 |
| H | 状況 | 未着手 / 進行中 / 完了 / 保留 |
| I | 進捗率 | `70%` `70` `0.7` のいずれでも入力可 |
| J | 担当 | 担当者名 |
| K | 開発LT | `3h` `5.5h` 形式の工数 |
| L | 開始予定 | 開始予定日 |
| M | 完了予定 | 完了予定日 |
| N | 開始実績 | 実際の開始日 |
| O | 完了実績 | 実際の完了日 |

## タスクの入力方法

| 階層 | 入力列 | 例 |
|---|---|---|
| LV1 | C列 | 計画フェーズ |
| LV2 | D列 | 要件定義 |
| LV3 | E列 | ヒアリング |
| LV4 | F列 | 詳細確認 |

入力した列に応じて LV と No. が自動設定されます。既定の入力範囲は No.1000 までです。

## 日付と進捗の入力

1. L-M 列に開始予定と完了予定を入力します。
2. 作業開始時に N 列へ開始実績を入力します。
3. 作業中は I 列の進捗率を更新します。
4. 完了時は O 列へ完了実績を入れるか、B 列ダブルクリックで完了にします。

## よく使う操作

| 操作 | 内容 |
|---|---|
| B列ダブルクリック | 進捗率 100% と完了状態を反映 |
| C-F列で Shift + 右クリック | LV1 配下の折りたたみ / 展開 |
| K列で Shift + 右クリック | 配下末端タスクの開発LTを親行へ集計 |
| ガント更新 | 日付、進捗変更後に再描画 |
| 土日切替 | 土日列の表示 / 非表示 |
| 書式リセット | ヘッダー、罫線、休日色を再構築 |

完了行は、各 LV の塗り範囲に合わせて薄い灰色で表示されます。

## 親タスク自動再計算

1. 子タスクの `H:状況` `I:進捗率` `K:開発LT` `L:O` を更新すると、親タスクは自動で再計算されます。
2. 進捗率は開発LTの重み付き平均で計算されます。
3. 親タスクの状態は、遅延、完了、進行中、予定前、未着手の順で自動判定されます。

## C列の注意マーク

1. LV1 には注意マークは表示しません。
2. `!!` は期限超過の業務です。
3. `!` は今日着手または今日完了予定の業務です。
4. 今週着手予定だけでは、C列に追加の記号や塗りつぶしは出しません。

## 俯瞰シートの使い分け

| シート | 使いどころ |
|---|---|
| WBSサマリ | 月次で全体計画を俯瞰したいとき |

## よく使うマクロ

| マクロ | 内容 |
|---|---|
| `RunSetupWizard` | 初回セットアップ |
| `RefreshInazumaGantt` | ガント再描画 |
| `ExportToPDF` | 当月末までの PDF 出力 |
| `CreateRoadmapOverviewSheet` | WBSサマリ作成 |
| `CreateShowcaseSampleWBS` | 約150行のサンプルWBSを投入し、ロードマップも作成 |

## サンプルWBSの見どころ

1. テーマは「会話力向上アプリ『ハナセル』」です。
2. 完了タスクは、LV の塗り範囲と同じ幅で薄い灰色に統一表示されます。
3. サンプル投入時に `WBSサマリ` も同時生成されます。

## 困ったとき

| 症状 | 対処 |
|---|---|
| ガントが更新されない | `RefreshInazumaGantt` を実行 |
| 行挿入後に No. がずれた | タスク入力後に自動再採番されるか確認し、必要なら `RenumberRows` を実行 |
| 休日色がおかしい | `ResetFormatting` を実行 |
| 全体計画が見づらい | `CreateRoadmapOverviewSheet` を実行 |
