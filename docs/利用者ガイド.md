# 進捗管理表 利用マニュアル (v3)

更新日: 2026-04-11

## 表の見方

| 列 | 項目名 | 入力内容 |
|---|---|---|
| A | LV | 自動入力 |
| B | No. | 自動採番 |
| C-F | TASK | 階層に応じたタスク名 |
| G | タスク詳細 | 補足情報 |
| H | 状況 | 未着手 / 進行中 / 完了 / 保留 |
| I | 進捗率 | `70%` `70` `0.7` のいずれでも入力可 |
| J | 担当 | 担当者名 |
| K | 開発LT | `3h` `5.5h` 形式の工数 |
| L | 開始予定 | 開始予定日 |
| M | 完了予定 | 完了予定日 |
| N | 開始実績 | 実際の開始日 |
| O | 完了実績 | 実際の完了日 |

## タスクの入力方法

| 階層 | 入力列 | 例 |
|---|---|---|
| LV1 | C列 | 計画フェーズ |
| LV2 | D列 | 要件定義 |
| LV3 | E列 | ヒアリング |
| LV4 | F列 | 詳細確認 |

入力した列に応じて LV と No. が自動設定されます。既定の入力範囲は No.1000 までです。

## 日付と進捗の入力

1. L-M 列に開始予定と完了予定を入力します。
2. 作業開始時に N 列へ開始実績を入力します。
3. 作業中は I 列の進捗率を更新します。
4. 完了時は O 列へ完了実績を入れるか、B 列ダブルクリックで完了にします。

## よく使う操作

| 操作 | 内容 |
|---|---|
| B列ダブルクリック | 進捗率 100% と完了状態を反映 |
| C-F列で Shift + 右クリック | LV1 配下の折りたたみ / 展開 |
| K列で Shift + 右クリック | 配下末端タスクの開発LTを親行へ集計 |
| ガント更新 | 日付、進捗変更後に再描画 |
| 土日切替 | 土日列の表示 / 非表示 |
| 書式リセット | ヘッダー、罫線、休日色を再構築 |

## 俯瞰シートの使い分け

| シート | 使いどころ |
|---|---|
| WBS全体サマリ | フェーズ単位で進捗、工数、遅延を見たいとき |
| WBSロードマップ | 月次で全体計画を俯瞰したいとき |
| WBSダッシュボード | 朝会や定例で KPI と要注意タスクを確認したいとき |
| WBSフィルタビュー | 担当、状態、期限でタスクを絞り込みたいとき |

## よく使うマクロ

| マクロ | 内容 |
|---|---|
| `RunSetupWizard` | 初回セットアップ |
| `RefreshInazumaGantt` | ガント再描画 |
| `ExportToPDF` | 当月末までの PDF 出力 |
| `CreatePhaseSummarySheet` | 全体サマリ作成 |
| `CreateRoadmapOverviewSheet` | ロードマップ作成 |
| `CreateWBSDashboardSheet` | ダッシュボード作成 |
| `CreateWBSFilterViewSheet` | フィルタビュー作成 |
| `CreateShowcaseSampleWBS` | 約150行のサンプルWBSを投入 |

## 困ったとき

| 症状 | 対処 |
|---|---|
| ガントが更新されない | `RefreshInazumaGantt` を実行 |
| 行挿入後に No. がずれた | タスク入力後に自動再採番されるか確認し、必要なら `RenumberRows` を実行 |
| 休日色がおかしい | `ResetFormatting` を実行 |
| どこが遅れているか分からない | `CreateWBSDashboardSheet` または `CreateWBSFilterViewSheet` を実行 |
| 全体計画が見づらい | `CreateRoadmapOverviewSheet` を実行 |
