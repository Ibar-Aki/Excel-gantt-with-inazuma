## 目的

現行の InazumaGantt v3 / Lite は、ガント描画、イナズマ線、状況・進捗率同期、高速入力、WBS退避 / 復元、WBSサマリ、配布版受入テストまで整備済みである。

本メモでは、現行機能を前提に、次の改善候補を「利用者への効果」「実装の重さ」「検証観点」が分かる粒度で整理する。

## 調査した現行要素

- `README.md`: v3 / Lite の版構成、最近の運用改善、主要マクロ
- `docs/FEATURES.md`: 現行仕様、入力列、操作支援、補助シート
- `docs/WBS_改善アイデアレポート.md`: 過去の改善案と棚卸し
- `docs/高速入力_状況_進捗率仕様レポート.md`: 高速入力、状況・進捗率、ログ、状態チェック
- `dev/docs/ARCHITECTURE.md`: モジュール責務とデータ更新経路
- `vba/*_UTF8.bas`: 現行マクロ構成の概観

## 1. 遅延・期限接近レビューシート

### 内容

`遅延レビュー` シートを生成し、期限超過、3営業日以内の期限、開始予定日を過ぎても未着手、進捗率が低い高LTタスクを一覧化する。

### 現行機能との関係

現行では C列アラート、親タスク集計、WBSサマリがあるため、判定材料はかなり揃っている。次の段階では、シート上の警告表示だけでなく、会議でそのまま確認できる抽出一覧にする価値が高い。

### 実装イメージ

- 新規マクロ: `CreateDelayReviewSheet`
- 対象: v3 は `L:M` 予定日と `H:I:K:N:O`、Lite は実績列なし前提で判定
- 出力列: No.、LV、タスク名、担当、状況、進捗率、開発LT、完了予定、判定理由、推奨アクション
- 判定理由は `期限超過`、`期限接近`、`開始遅れ`、`高LT低進捗` などに正規化

### 検証観点

- 土日祝を含む期限接近判定が設定マスタの祝日と矛盾しない
- 完了済みタスクを遅延扱いしない
- v3 / Lite の列差分で誤参照しない
- 大量行でも生成時間が実用範囲に収まる

## 2. 担当者別負荷・残工数ビュー

### 内容

`担当別負荷` シートを生成し、担当者ごとの総LT、残LT、進行中件数、今週期限件数、遅延件数を集計する。

### 現行機能との関係

親タスク集計により階層ごとの LT は扱いやすくなっている。一方、担当者単位の偏りは現行の WBSサマリでは見えにくい。

### 実装イメージ

- 新規マクロ: `CreateAssigneeLoadSheet`
- 末端タスクを中心に集計し、親タスクとの二重計上を避ける
- 残LTは `開発LT * (1 - 進捗率)` を基本とする
- 担当未入力は `未設定` として分離

### 検証観点

- 親行と子行の LT を二重計上しない
- `3`、`3h`、`3.5h`、空欄など既存の LT 正規化仕様と整合する
- 保留タスクを残LTに含めるかどうかを設定化できる

## 3. WBS整合性チェック

### 内容

`WBS整合性チェック` シートを生成し、開始日 > 完了日、完了なのに完了実績日なし、未着手なのに実績日あり、進捗率と状況の不一致、担当なしなどを一覧化する。

### 現行機能との関係

現行の入力時バリデーションは有効だが、貼り付け、高速入力 ON 中、外部復元後のまとめ検査には専用の監査シートがあると強い。

### 実装イメージ

- 新規マクロ: `CreateWbsIntegrityCheckSheet`
- エラー種別を `ERROR` / `WARN` / `INFO` に分類
- 対象セル番地、現在値、期待状態、修正ヒントを出力
- `CheckInazumaRuntimeState` と併用して、ブック状態とデータ状態を分けて確認する

### 検証観点

- 高速入力 ON/OFF 復帰後に誤検知が残らない
- 進捗率 `0.7` / `70` / `70%` の正規化後状態で判定する
- v3 の実績列と Lite の列差分を明確に分ける

## 4. 週次レビュー出力

### 内容

`週次レビュー` シートを生成し、先週完了、今週期限、遅延、保留、リスク候補を会議用にまとめる。

### 現行機能との関係

WBSサマリは全体俯瞰に強いが、週次会議で必要な「今見るべき項目」には別の切り口が必要になる。

### 実装イメージ

- 新規マクロ: `CreateWeeklyReviewSheet`
- 期間は今週を既定にし、必要に応じて入力ボックスで基準日を指定
- PDF 出力と組み合わせ、会議配布用に A4 横で整える

### 検証観点

- 週開始日の扱いを月曜始まりで固定するか設定化する
- 完了実績日がある v3 と、実績列がない Lite で出力内容を変える
- PDF 出力時に列幅、改ページ、文字切れが起きない

## 5. ベースライン / スナップショット

### 内容

現在の WBS 状態を `Baseline_YYYYMMDD` または `Snapshot_YYYYMMDD` として保存し、計画変更、進捗差分、LT差分を比較できるようにする。

### 現行機能との関係

WBS退避 / 復元は直近の安全退避に強い。一方、計画変更の履歴説明や振り返りには、複数時点の保存と比較が必要になる。

### 実装イメージ

- 新規マクロ: `CreateWbsSnapshotSheet`
- 新規マクロ: `CreateBaselineDiffSheet`
- 保存対象は `A:O` とし、ガント図形は保存しない
- スナップショット一覧を設定マスタまたは専用管理シートに持つ

### 検証観点

- シート数が増えた場合のファイルサイズと操作性
- 現行の `WBS_Backup_*` と用途が混同されない命名
- 復元用途ではなく比較用途であることを画面文言で明確にする

## 6. 入力支援メニュー

### 内容

選択行を起点に、子タスク追加、同階層タスク追加、担当者コピー、予定日シフト、テンプレート挿入を実行できる導線を追加する。

### 現行機能との関係

現行はボタンと Shift + 右クリック操作がある。機能が増えるほどマクロ名を覚える負担が増えるため、入力操作の近くに導線を寄せると利用者の迷いが減る。

### 実装イメージ

- 右クリックメニュー拡張、または上部ボタン追加
- 行追加後は `AutoDetectTaskLevelsInRange`、`RenumberRowsForWorksheet`、親集計を呼び出す
- 高速入力 ON 中の挙動を通常入力と分けて定義する

### 検証観点

- Excel 標準の右クリック操作を壊さない
- 高速入力 ON 中に Undo 優先仕様と衝突しない
- 行追加後の LV、No.、親集計、ガント更新が一貫する

## 7. CSV / TSV 入出力

### 内容

外部台帳、チケット管理、別 Excel から WBS を取り込めるよう、CSV / TSV のインポート・エクスポートを用意する。

### 現行機能との関係

配布 bundle と復元スクリプトは整備済みだが、業務データそのものの外部連携はまだ限定的である。

### 実装イメージ

- 新規マクロ: `ExportWbsToCsv`
- 新規マクロ: `ImportWbsFromCsv`
- 列名ベースで取り込み、列順変更に強くする
- インポート前にプレビュー / 整合性チェックを挟む

### 検証観点

- 文字コードは Excel / PowerShell / cmd.exe の経路で文字化けしないように扱う
- 列名ゆれ、空列、余分な列を安全に処理する
- インポート失敗時は既存 WBS を壊さない

## 8. 配布前チェック結果の自動レポート化

### 内容

受入テスト結果、配布版生成結果、bundle 復元結果をまとめて `docs/` に出力し、出荷判断の根拠を毎回同じ形式で残す。

### 現行機能との関係

すでに `dev/tools/Invoke-InazumaAcceptanceTests.ps1` と受入結果ドキュメントが存在する。次の改善は、手作業の記録揺れを減らし、配布物、復元、再オープン、スモークの結果を一枚に集約すること。

### 実装イメージ

- PowerShell 側で `acceptance-results.json` を読み、Markdown サマリを生成
- 対象ブック、OK/NG件数、実行日時、出力パス、確認観点を固定フォーマット化
- `distribution_v3` / `distribution_lite` の両方を必ず載せる

### 検証観点

- NG がある場合に成功扱いのレポートを作らない
- 配布版と bundle 復元相当の確認有無を分けて表示する
- 出力先の古い結果と混同しないファイル名にする

## 推奨する着手順

### Phase 1: 現場効果が大きく、既存構造を活かせるもの

1. 遅延・期限接近レビューシート
2. WBS整合性チェック
3. 担当者別負荷・残工数ビュー

この 3 件は、既存のタスク列、進捗率、開発LT、親集計、祝日設定を活用できるため、比較的少ない構造変更で効果が出やすい。

### Phase 2: 会議・報告の手間を減らすもの

1. 週次レビュー出力
2. 配布前チェック結果の自動レポート化

運用の繰り返し作業を減らす目的で、出力形式と検証観点を先に固めてから実装する。

### Phase 3: 変更履歴・外部連携など影響範囲が広いもの

1. ベースライン / スナップショット
2. CSV / TSV 入出力
3. 入力支援メニューの本格拡張

これらは便利だが、既存データ破損、列差分、Undo、ファイルサイズ、運用ルールに影響しやすい。先に仕様を小さく切って、受入テストを追加してから進める。

## 次に具体化するなら

最初に実装候補へ落とすなら、`WBS整合性チェック` が最も扱いやすい。理由は、既存データを変更せず読み取り中心で実装でき、検証しやすく、以後の CSV 取込やスナップショット比較の前提品質も上げられるためである。

次点は `遅延・期限接近レビューシート`。利用者への効果は大きいが、判定条件の業務解釈が入るため、最初は判定種別を少なくして始めるのがよい。
